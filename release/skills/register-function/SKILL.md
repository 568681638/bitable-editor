# 把函数注册进批处理函数注册表

目标：给一个现成的函数写一个**适配层**（一个函数文件夹 + 入口 `function.py` / `function.mjs`），让服务端能加载它、面板能选到它、`run(rows)` 能按约定批量调用它。**原函数的逻辑不改**，适配层只负责“行 ↔ 参数”“返回值 ↔ 出参”的转换。

## 0. 先读规则，再确认服务

1. **完整读一遍 `release/server/functions/README.md`**。它是唯一的规则来源（入参 / 出参 / `run` 的约定、出参值格式、两个开关、不来自字段的入参、热加载、Python 运行方式）。本 skill 只讲流程和容易错的地方，规则以 README 为准；两者不一致时以 README 为准，并告诉用户。
2. 确认服务在跑、是新版本：
   ```bash
   python -I release/skills/register-function/check_function.py --list
   ```
   能列出函数、并且显示“服务端版本：新”才继续。连不上就让用户先启动服务（`npm run serve`，或按 `release/README.md` 部署），**不要自己去改部署**。端口不是 6868 时加 `--base http://127.0.0.1:<端口>`。

## 1. 弄清楚原函数

动手前先回答这些问题，答不上来的问用户，不要猜：

| 问题 | 为什么要知道 |
| --- | --- |
| 语言、入口在哪（文件、函数名 / 类方法）、签名是什么 | 决定写 `function.py` 还是 `function.mjs`，以及怎么调用它 |
| 一次处理一条还是一批？有没有批量版本的下游接口 | `run(rows)` 是批量接口：下游支持批量就合并成一次请求，不支持就在 `run` 里循环（必要时控制并发） |
| 每个参数是**每行不同的数据**，还是**一次运行的设置**（模式、语言、阈值、提示词…） | 前者映射到字段，后者用 `select` / `multiSelect` / `text` 入参（见第 3 步） |
| 参数要什么类型（字符串、数字、列表、日期…） | 字段入参传进来的**一律是文本**，要在适配层里转换 |
| 返回什么、要写到什么类型的字段 | 出参值必须是目标字段类型的原生形态（README“出参值的格式”） |
| 依赖哪些文件、第三方库、凭证、外部服务 | 函数必须自包含（第 2 步）；凭证走 `_config` / 环境变量，不能硬编码 |
| 单次耗时多久、有没有限流 | 决定 `batchSize`、是否 `async: true` |
| 有没有“读取—判断—写入”同一份外部数据这类多步副作用 | 两次执行交错会出错就要 `serializeCalls: true` |
| 哪种情况算“这一行失败”，哪种算“整批失败” | 单行失败返回错误对象，系统性故障才抛异常 |

## 2. 建函数文件夹

- 位置：`release/server/functions/<分类目录…>/<函数文件夹>/`。分类目录可以多层，面板里的层级和目录结构一致；问用户放哪个分类，没有合适的就新建。
- 文件夹名就是默认的 `id`：用小写英文 + 下划线，**不能以 `_` 或 `.` 开头**；先 `--list` 确认没有重名的 `id`（重名的会被忽略，只在日志里报警）。
- 从 `release/server/functions/_template/` 复制模板，`function.py` / `function.mjs` 只留一个。
- **自包含**：原函数的代码和它依赖的本地模块、数据文件，**复制进这个文件夹**（例如 `xxx_client.py`），在入口里 `import`。不要 `import` 项目外的路径、不要用绝对路径 —— 部署到服务器上就找不到。多个函数共用的才放 `functions/` 根目录、以 `_` 开头。
- 原函数在别的仓库、以后还会更新时，在复制过来的文件开头注明来源（仓库 / 路径 / 版本），方便以后同步。

## 3. 设计入参和出参

**入参**（`inputs`）：
- 每行不同的数据 → 不写 `type`，用户在面板里映射到字段。`run` 拿到的是**字符串**（单元格拍平成文本；没映射的可选入参不会出现在 `row` 里），需要数字 / 列表 / JSON 的，在适配层里解析，解析失败就让这一行失败。
- 一次运行的设置 → `type: 'select'`（`options` 必填）/ `'multiSelect'`（`options` 必填，`run` 拿到字符串数组）/ `'text'`；写上 `default`，**一定写 `description`**（面板里这类入参的含义只能靠它说明）。原函数参数有默认值的，通常就是这一类。
- `name` 用原函数的参数名（或贴近的英文），`label` 用中文，面板里显示。

**出参**（`outputs`）：
- 原函数返回多个值（字典、元组、对象）时，每个要写进表格的值是一个出参；`label` 写清楚含义。
- 某个出参只依赖部分入参时写 `requires`，用户只选这个出参时就不会被要求映射无关的入参。
- 函数除了返回值，还能说明“这次执行得怎么样”（即执行详情）（命中缓存、重试次数、被截断的行、整批统计）时，加执行详情：出参写 `{"name": "report", "label": "执行详情", "type": "detail"}`（每行一条，没有就返回 `None`），或者 `run` 返回 `{"results": [...], "detail": "整批详情"}`（每批一条）。它不写进字段、面板在「历史」里展示；详情是纯文本，别写凭证。原函数没有这类信息就不用加。
- 只有副作用、不往表格写值的函数（发通知、触发任务），`outputs` 写 `[]`，`run` 每项返回 `{}`。
- 返回值按目标字段类型给原生形态：数字字段给数字、日期给**毫秒时间戳**、单选给选项名、多选给选项名数组、复选框给布尔值……不确定会写到什么字段时问用户。某行没有值、不想覆盖字段：返回 `None` / `null`（JS 里不能是 `undefined`）。

## 4. 写 `run(rows)`

约定（细节见 README“`run(rows)` 的约定”）：
- 返回值必须是**与 `rows` 等长、顺序一致**的列表，每项是 `{出参名: 值}`。
- 某一行失败：在那个位置**返回**错误对象（Python `ValueError('原因')`，JS `new Error('原因')`），不要 `raise` / `throw`；原因写成用户看得懂的中文，带上关键的值。
- 整批失败（下游整个不可用、凭证缺失）：直接抛异常，运行会中断并提示原因。
- 同一批合并成一次下游请求；下游只能逐条调用时，在 `run` 里循环，耗时长的用线程池并发（参考 `asset_time/function.py` 的 `ASSET_WORKERS`），注意下游限流。
- Python：第三方库和慢的模块**在 `run` 里再 `import`**，导入失败也不会让函数从列表里消失；工作目录就是函数文件夹，可以直接 `import` 同文件夹的模块、按相对路径读数据文件；`print` 进服务日志。
- JS：服务端要兼容 **Node 14**（不用 `??=`、`||=`、`replaceAll`、`.at()`）；读同文件夹的文件用 `new URL('./data.json', import.meta.url)`；入口 `import` 的其他 `.mjs` 改了要重启服务才生效。

Python 适配层的骨架（JS 同理，见 `_template/function.mjs`）：

```python
# 适配：<原函数来源>。原逻辑在 <模块>.py，这里只做行 ↔ 参数、返回值 ↔ 出参的转换
META = {
    "name": "中文函数名",
    "inputs": [
        {"name": "text", "label": "文本"},                                   # 来自字段：拿到的是字符串
        {"name": "lang", "label": "语言", "type": "select",
         "options": [{"value": "zh", "label": "中文"}, {"value": "en", "label": "英文"}],
         "default": "zh", "description": "结果使用的语言"},
    ],
    "outputs": [{"name": "summary", "label": "摘要"}],
    # "batchSize": 20, "async": True, "serializeCalls": True,  # 按需
}


def run(rows):
    from my_module import summarize          # 依赖放在 run 里 import
    results = []
    for row in rows:
        text = (row.get("text") or "").strip()
        if not text:
            results.append(ValueError("文本为空"))   # 单行失败：返回，不是 raise
            continue
        try:
            results.append({"summary": summarize(text, lang=row.get("lang", "zh"))})
        except Exception as e:                        # 原函数对这一行报错：只让这一行失败
            results.append(ValueError("摘要失败：%s" % e))
    return results
```

## 5. 选开关

| 情况 | 写法 |
| --- | --- |
| 一批要跑几分钟以上 | `async: true`（Python `"async": True`）。Python 单批超时变成 4 小时；回写需要插件页面开着 |
| 两次执行交错会出错（多步副作用） | `serializeCalls: true`。同一时间最多一个 `run` 在跑，会变慢，没必要就别加 |
| 下游一次能处理很多 / 很慢、限流 | `batchSize`（默认 100，范围 1–5000）调大 / 调小 |

都不需要就什么都不写。不要为了“保险”乱加开关。

## 6. 验证（必须做完）

1. 保存后服务自动热加载。用检查脚本确认注册成功、声明和预期一致，并用样例行实际调用一次：
   ```bash
   # rows.json 里放 2～5 行真实一点的样例，至少包括一行正常、一行应该失败的
   python -I release/skills/register-function/check_function.py <函数 id> --rows rows.json
   ```
   脚本会检查：函数在列表里、入参出参和开关、调用返回与行数等长、每行要么成功且带齐出参、要么有失败原因；有执行详情时会把各行和整批的详情打印出来。有 `FAIL` 就修，直到全部通过。异步函数的 `/run` 也是当场执行，同样适用。
2. **没出现在列表里**：看服务日志里 `[functions]` 开头的行（语法错误、定义不合法、某个入参声明不合法、`id` 重复，都会写明原因）。
3. 原函数自己有测试或已知的输入输出时，用它们对照适配层的结果。
4. 只在这一步之后，再让用户去面板里试：选函数 → 映射字段 / 填设置 → 运行。

## 7. 收尾时告诉用户

- 函数放在哪、`id` 和面板里的名字、在哪个分类下。
- 每个入参：来自字段还是在卡片里选 / 填，需要什么格式；每个出参建议写到什么类型的字段。
- 开了哪些开关、为什么；`batchSize` 是多少。
- 依赖：需要在服务器上装哪些 Python 包、配哪些凭证（`_credentials.json` 或环境变量），这些**部署时要手动处理**。
- 验证结果（检查脚本的输出摘要）；没验证到的部分（比如需要真实凭证的下游调用）如实说明。

## 常见错误

- 把字段入参当成数字 / 列表直接用（它是字符串）。
- `run` 返回的列表长度和 `rows` 不一致（跳过了失败的行、或者把批量结果展开了）→ 整批失败。
- 单行失败用了 `raise` / `throw` → 整批失败。
- 日期返回字符串、单选返回不存在的选项名 → 写回时这一行失败。
- `import` 了项目外的代码、写了本机绝对路径 → 本地能跑，服务器上找不到。
- 凭证写死在代码里 → 用 `_config.py` / 环境变量（参考 `asset_time`、`tte_issue`）。
- Python 顶层 `import requests` 等第三方库 → 服务器没装时函数直接从列表消失，应放进 `run`。
- 文件夹名以 `_` 开头、或者入口文件不叫 `function.py` / `function.mjs` → 不会被加载。
- 原函数不是 Python / JS（命令行工具、别的语言、HTTP 服务）：用 Python 写适配层，在 `run` 里用 `subprocess` 或 `requests` 调它，同样遵守上面的约定；外部程序要在服务器上可用。
